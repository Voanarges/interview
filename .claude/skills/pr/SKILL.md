Сгенерируй описание Pull Request для текущей ветки.

## Шаги

1. Выполни `git log main...HEAD --oneline` — посмотри все коммиты
2. Выполни `git diff main...HEAD --stat` — список изменённых файлов
3. Определи тип изменений: новая фича / баг-фикс / рефакторинг / тесты / конфиг
4. Сгенерируй описание по шаблону ниже

## Шаблон PR (на русском языке, как принято в проекте)

```markdown
## Что сделано

- <конкретное изменение 1>
- <конкретное изменение 2>
- <конкретное изменение 3>

## Почему

<Контекст: какую проблему решает или какую фичу добавляет>

## Как проверить

- [ ] `yarn nx test api --no-coverage` — тесты проходят
- [ ] `yarn typecheck` — нет TypeScript ошибок
- [ ] <специфичный шаг проверки для этого PR>

## Затронутые модули

<список модулей/компонентов из diff>

## Риски и edge cases

<что может пойти не так, на что обратить внимание при ревью>
```

## Правила для текущего проекта PR

- Заголовок PR: краткий, до 70 символов, начинается с глагола (Добавить / Исправить / Рефакторинг)
- Если затрагивает AI/RAG — упомяни токены и возможное влияние на расходы
- Если затрагивает Redis/блокировки — проверь TTL и ключи
- Если затрагивает Prisma — убедись что есть миграция, не `synchronize: true`
- Если затрагивает WebSocket/Socket.io — проверь JWT в `handleConnection`
