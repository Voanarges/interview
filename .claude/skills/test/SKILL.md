Запусти тесты для контекста текущей задачи.

Правила выбора команды:
1. Если указан конкретный файл или модуль (`$ARGUMENTS`) — запусти тесты только для него
2. Если аргумент не указан — определи по текущему контексту разговора, какой модуль менялся, и запусти его тесты
3. Всегда используй `--no-coverage` для скорости
4. Если тесты падают — покажи конкретную причину и предложи исправление

## Команды для запуска тестов в текущего проекта

```bash
# Конкретный модуль API
yarn nx test api --testPathPattern="apps/api/src/modules/<module>" --no-coverage

# Один тестовый файл
yarn jest <путь/к/файлу.spec.ts> --no-coverage

# Все тесты API (медленно)
yarn nx test api --no-coverage

# Затронутые тесты (по diff от main)
yarn nx affected --target=test --no-coverage
```

## Что проверять если тесты упали

1. **fire-and-forget** — добавь `await flushPromises()` после void промисов
2. **Новая зависимость в конструкторе** — добавь мок в `makeService()` вызовы
3. **Изменился формат данных** — обнови expect() в тестах под новую структуру
4. **Таймауты** — используй `jest.useFakeTimers()`, никогда `setTimeout` в тестах
