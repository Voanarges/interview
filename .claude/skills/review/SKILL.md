Проведи полный adversarial code review для проекта текущего проекта в 3 фазы.

## Подготовка

1. Определи что ревьюить:
   - Если указан `$ARGUMENTS` (путь к файлу или модулю) — ревью только его diff
   - Если аргумент не указан — ревью всех изменений текущей ветки относительно main
2. Получи diff: `git diff main...HEAD` (или `git diff` для unstaged изменений если на main)
3. Прочитай все изменённые файлы целиком (не только diff — нужен контекст)

## Фаза 1: Attack (прокурор)

Запусти Agent с ролью hostile reviewer. Передай ему полный diff и содержимое `.claude/skills/review-attack/SKILL.md` как инструкцию. Агент должен найти все проблемы по категориям:
- Безопасность (prompt injection, SQL injection, XSS, секреты, CORS, JWT)
- Архитектура (FSD нарушения, прямой HTTP вместо RabbitMQ, типизация)
- AI/RAG (утечка ключей, батчинг, threshold, стриминг)
- Тесты (покрытие, антипаттерны)
- NX монорепо (импорты, экспорты, page.tsx)

## Фаза 2: Defense (адвокат)

Запусти Agent параллельно с Attack. Передай ему тот же diff и содержимое `.claude/skills/review-defend/SKILL.md`. Агент должен подготовить защиту с учётом контекста (test vs prod, архитектурные компромиссы, покрытие на уровне gateway).

**ВАЖНО: Attack и Defense запускаются ПАРАЛЛЕЛЬНО через два Agent вызова в одном сообщении.**

## Фаза 3: Verdict (судья)

После завершения обоих агентов — запусти третий Agent с ролью судьи. Передай ему:
- Результат Attack
- Результат Defense
- Исходный diff
- Содержимое `.claude/skills/review-verdict/SKILL.md` как инструкцию

Судья выносит объективный вердикт: APPROVE / REQUEST CHANGES / NEEDS DISCUSSION.

## Вывод результата

Покажи пользователю финальный отчёт в формате:

```
# Adversarial Review: [цель ревью]

## 🔴 Attack
[результат атаки]

---

## 🟢 Defense
[результат защиты]

---

## ⚖️ Verdict
[вердикт судьи]
```

## Правила

- НЕ спрашивай подтверждение — запускай сразу
- Attack и Defense — ПАРАЛЛЕЛЬНО (два Agent в одном сообщении)
- Verdict — ПОСЛЕ завершения обоих
- Если diff пустой — сообщи и останови
